## 第五阶段实施记录（2026-09-09）

### 已完成

- 新增 `server/config.js`、`server/database.js`、`server/telemetryProcessor.js`、`server/api.js`、`server/index.js`。
- 使用 Node.js 26.3.0 自带 `node:sqlite`，历史服务直接订阅 MQTT TCP，不依赖浏览器存活。
- 新增 `metadata`、`batches`、`hourly_production`、`speed_samples`、`alarm_events` 五张表；数据库默认保存于 `data/project2.sqlite`（历史兼容文件名）。
- 批次、小时产量和报警保存 365 天；速度按每分钟最后一个有效 HD62 保存 90 天；启动和每 6 小时自动清理超期数据。
- 持久化 HD40 批次状态、报警边沿和计数；首条报文只建基线；正值后连续两条 0 才切换；重复 0 不重复创建；跨自然日不切换当前批次。
- M9 仅 `1 -> 0` 触发；T100-T128 仅 `0 -> 1` 触发；服务重启从 SQLite 恢复状态。T122/T123/T126/T127 使用已现场确认的名称和地址，其他 T 只保留原始代码。
- 新增只读 `/api/health`、`/api/meta`、`/api/daily`、`/api/batches`、`/api/hourly`、`/api/speeds`、`/api/alarms`。
- 前端生产记录、历史报警、每日/每小时图表和速度历史优先读取 API；实时状态和当前报警由浏览器 MQTT 负责。
- API 不可用时页面显示“历史服务不可用”，历史页面不再显示旧样例或模拟记录；没有实时报文时指标显示 `--`。
- MQTT、HTTP、数据库路径和保留期限支持环境变量；账号密码不再写入前端源码。
